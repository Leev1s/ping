# 多设备人机工学建议

研究范围：参考 [CF 网络状态页](https://cf.090227.xyz/#/network)，以及 WCAG、Apple、Android 与 MDN 的当前公开规范。本文为 Ping 的产品验收建议，不宣称页面已经达到这些目标。

## 结论

将“打开就能看到主要状态，不必先滚动”作为常规设备的目标；把“每个设备、所有高度、系统字体放大后永不滚动”作为不可保证的要求。WCAG 2.2 的 Reflow 以 **320 CSS px 宽度**验证单方向滚动，不要求整页高度塞进当前屏幕；放大文字、浏览器界面和安全区还会继续压缩实际可见高度。遇到这些情况时，纵向滚动应恢复，让文字、控制和八个探针仍可达，不能裁切或整体缩小来伪造单屏。

## 布局建议

参考页的可读之处是信息对象少、组名明确、延迟数字直接靠近服务名称。Ping 保留这个顺序，去掉大标题、副标语、解释段落、装饰插图和重复页脚。页面只回答“主探针现在多少”“四个中国大陆与四个国外服务各是多少”“刷新是否持续”。

| 视口 | 固定范围的呈现 | 验收目标 |
| --- | --- | --- |
| 桌面，1440×800 和 1280×720 | 顶栏与主读数在上；中国大陆/国外各一个紧凑组，每组四个等高行或 2×2 单元；统计分布占一块固定大小的共享区域。 | 单屏见八个名称、八个当前数字、两组分类及主统计；采样不改变卡片高度、网格或页面滚动高度。 |
| 平板，768×1024 | 两组并列；次要统计合并为数值条；过滤器与控制集中在固定工具条。 | 内容不被设备折叠区遮挡；横竖屏切换后组与行顺序稳定。 |
| 手机竖屏，375×667、320×568 | 删除介绍文案，只显示品牌/控制、一个主数字条和两组各四行。每行固定网格：名称、数值、状态符号；沿用列宽，数字变动不推挤其他行。 | 100% 默认字体且浏览器内容视口满足相应尺寸时，打开即看到八个探针，无横向和纵向滚动。320px 时按两列或紧凑表格排组，不能将文字压到难以阅读。 |
| 手机横屏，667×375 | 减少外边距，工具、主数值、八个探针固定在紧凑两列；去掉对网络判断没有帮助的副指标和装饰。 | 100% 默认字体、无浏览器弹出面板且内容视口满足尺寸时无滚动；工具栏和八个探针不被刘海/圆角截断。 |
| 320 CSS px、200% 文字或 400% 浏览器缩放 | 维持正常字级和可读列；必要时按自然顺序纵向重排。 | 无横向页面滚动、信息不丢失，所有控制可聚焦；允许纵向滚动。这符合“文字和功能可重排”的可访问性优先级。 |

“尺寸”必须记录 **CSS 内容视口**而非设备像素或机身屏幕尺寸。浏览器地址栏、标签栏、分屏、系统字体、虚拟键盘和安全区都会使实际可用的 `innerHeight`/视觉视口变小。手机全屏高度按 `100dvh` / `visualViewport` 观察；支持全面屏时以 `env(safe-area-inset-*)` 给边缘留空。不要仅用 `100vh` 锁死大视口高度，不要用 `overflow:hidden` 隐藏溢出；当可用高度不足时，允许页面滚动。

## 手指、文字与色彩

- 可点击的暂停、语言、采样间隔和刷新控制，触摸区域以 **44×44 CSS px** 为目标；绝对紧凑下限也不低于 WCAG AA 的 24×24 px，彼此留出明确间距。八条探针只是数据，不做成八个小按钮，避免制造 8 个无用触摸目标。关键操作在拇指自然可及的位置，图标按钮保留可见或无障碍名称。
- 普通文字前景与底色对比度至少 **4.5:1**，大字至少 **3:1**；控件边界和关键状态指示至少 **3:1**。成功/慢/失败不能仅靠绿黄红区分，要同时显示数字、短文本或形状，暗色调色板中次要文字也要通过数值验证，而不是凭肉眼选灰色。
- 页面只选三套字体：**中文/拉丁界面无衬线、英文强调无衬线、等宽数字字体**。明确指定可用字体及回退链；名称、说明和按钮均使用同一界面字族，特殊强调只在品牌小字使用第二字族，所有数值共用等宽字族。繁简字符与拉丁字母检查字重、基线和宽度；字体加载失败时仍应回退到系统无衬线/等宽，不引入额外第四种强调字体。手机常规说明不要小于约 12 CSS px，核心延迟数字显著更大。
- 运动区域保持固定宽高、固定坐标和标签：下一次采样只能更换值、状态和一段固定范围的图形；长短数字都对齐同一单元，不触发布局重排。尊重 `prefers-reduced-motion`；状态可读且不会闪烁夺走注意力。

## 可复验的验收

1. Chromium 视口依次设为 1440×800、1280×720、768×1024、375×667、320×568、667×375。分别以 100% 和 200% 字体检查 `window.innerWidth/innerHeight`、`scrollWidth/scrollHeight`、`visualViewport` 与 safe area；记录浏览器、方向、缩放。常规目标机型必须页面不滚动；200% 文字/高缩放只要求无横向滚动、内容可完整纵向访问。
2. 对每一种语言和八个目标，检查名称、分区、当前数字、失败状态都在；不同数位长度、超时和恢复都不会改变一行高度、列宽、卡片位置或页面高度。至少连续采样 20 轮对照首帧和末帧。
3. 检查四个触摸/交互控件包围盒，验证目标尺寸和间距；使用对比度计算器计算文本、状态文本、图标轮廓与背景的比值。实际设备上以单手拇指触达主暂停控制。
4. 用系统动态字体放大、浏览器 200%/400% 缩放、手机浏览器栏展开/收起和横竖屏旋转检查；页面按自然顺序重排，必要时出现纵向滚动，不隐藏焦点或探针。

## 一手规范

- [W3C WCAG 2.2：Reflow，1.4.10](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)：320 CSS px 的单方向重排边界。
- [W3C WCAG 2.2：Contrast Minimum，1.4.3](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)：普通文本 4.5:1，大号文字 3:1。
- [W3C WCAG 2.2：Target Size Minimum，2.5.8](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)：AA 的 24×24 px 控件目标及间距例外；[Enhanced，2.5.5](https://www.w3.org/WAI/WCAG22/Understanding/target-size-enhanced.html) 的 AAA 目标为 44×44 px。
- [Apple Design Tips](https://developer.apple.com/design/tips/) / [Apple Buttons HIG](https://developer.apple.com/design/human-interface-guidelines/buttons)：44pt 触控区、内容贴近控制，以及重要内容无需缩放或横向滚动的建议。
- [Android 可访问性触控目标](https://developer.android.com/guide/topics/ui/accessibility/views/apps-views)：推荐每个可交互目标至少 48×48 dp。
- [MDN 动态视口单位 `dvh`](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/length#dynamic_viewport_units)、[安全区环境变量](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/env) 与 [Viewport concepts](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/CSSOM_view/Viewport_concepts)：浏览器 UI 改变可见视口、移动端设备宽度与安全区处理。
