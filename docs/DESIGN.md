# Ping 产品与实现决策

## 核心问题

这个单页只回答三件事：当前浏览器访问目标服务需要多久、最近是否波动、访问 Cloudflare 使用哪个出口。参考站的服务卡片是起点；持续采样、可追溯趋势和测量可信度是主要差异。调研证据见 [RESEARCH.md](RESEARCH.md)。

## 功能与边界

| 用户问题 | 实现 | 验收 |
| --- | --- | --- |
| 延迟是否一直更新？ | 每个端点独立循环，3/5/10 秒可选；请求超时 4.5 秒；不重叠同一目标请求。 | NET-1/2/3 |
| 最近是否稳定？ | 最近 60 次采样，Cloudflare 中位数、P95、相邻样本抖动和 HTTP 失败率。失败点红色标记，趋势不跨失败连线。 | DATA-1 |
| 当前走哪个出口？ | 免费 Cloudflare trace；显示国家、边缘和 TLS，IP 默认隐藏。 | DATA-2/PRIV-1 |
| 能否相信这个“可达”？ | CORS 可读状态与 opaque 耗时分开；opaque 明确标为未验证。HTTP 耗时不能冒充 ICMP、丢包或整个网络质量。 | NET-2 |
| 是否容易部署？ | Vite 静态产物直接交给 Cloudflare Workers，GitHub CI，双语部署文档。 | DEP-1/CI-1 |

## 界面

采用深色观测仪表台：荧光绿强调正在变化的读数，等宽数字便于比较；左侧时间序列与目标列表，右侧出口信息和测量解释。移动端改成单列和两列指标卡。动效只用于实时数值（Magic UI Number Ticker）和采样提示，并尊重减少动态效果设置。中英切换与采样间隔只在本机持久化。

## 名称与域名

用户确定品牌为 **Ping**、仓库为 `Leev1s/ping`、域名为 `ping.r3.net.eu.org`。`ping` 对应主动网络探测，短子域名适合经常打开的工具；页面明确解释其 HTTP 测量语义。沿用用户已有 Cloudflare 区域，无需购买域名，也不新增第三方 API 密钥或代理服务。

## 奥卡姆剃刀

只保留 React、TypeScript、Vite、图标与 Magic UI 所需的 motion。SVG 直接绘制趋势，不引入图表、状态管理或 i18n 框架。没有数据库、登录、历史服务、服务端转发、带宽测速或任意 URL 探测。样本留在内存，导出显式排除连接身份。公开端点的可用性和策略由服务商控制，失败如实呈现，不用静态数据替补。
