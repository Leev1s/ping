# 连续探针的数据呈现建议

## Cloudflare Speed Test 学习结论

[Cloudflare Speed Test](https://speed.cloudflare.com/) 把下载、上传、空载延迟、抖动和丢包分开展示；完整测量之后还可查看原始结果。[官方说明](https://speed.cloudflare.com/about)介绍延迟为浏览器开始收到响应数据的时间（TTFB）、抖动为相邻 ping 样本的平均差。[Cloudflare 博客](https://blog.cloudflare.com/how-does-cloudflares-speed-test-really-work/)进一步说明吞吐测试是多个数据块的分组结果，以箱须图展示范围和百分位；空载 ping 在连续阶段开始时测，加载延迟则在下载/上传期间另发轻量请求。[官方测量引擎 README](https://github.com/cloudflare/speedtest/blob/main/README.md)列出了延迟点、相邻点抖动、加载延迟和带宽结果等独立序列。

可迁移的是“指标分开、样本形成分布、每个时间窗有固定边界”。不能迁移的是 Cloudflare 专用的网络质量分数、上传/下载速度、负载下延迟及 TURN packet loss：Ping 并未执行相应测量。

## Ping 的统计对象

八个探针代表八个不同域名和网络路径。默认每个域名独立每 5 秒采样，历史窗口固定为最近 60 个样本。不得把大陆与海外域名的延迟拼在一起算一个平均数，亦不得用一个探针代表浏览器访问其它域名的 HTTP 延迟。

对于一个能读取状态码的目标，窗口统计定义如下：

- **当前**：该目标最新一次成功或 opaque 响应的 HTTP 请求耗时。最新请求失败时显示破折号；已读取的 HTTP 错误响应耗时仅保留于原始样本，不作为当前有效读数。
- **P50**：窗口有效耗时的中位数，描述典型请求。偶数样本取中央两个数均值。
- **P95**：升序样本索引 `ceil(0.95 × n) − 1` 的值。只在 `n >= 40` 时显示；更少时在固定槽位显示 `—`，标签工具提示说明 40 样本门槛，不要用单样本放大图暗示已掌握分布尾部。滚动 60 次窗口的 P95 仍只有约 3 个上尾样本，应视为短窗参考值，不用于 SLA 或“网络质量评分”。
- **抖动**：沿用 Cloudflare 的相邻延迟绝对差定义：`mean(|x[i] − x[i−1]|)`。只计算时间上真正相邻且两次都得到响应头的有效样本；中间有超时/失败则该对不参与。称作“HTTP 延迟变化”，避免令用户误以为有 ICMP jitter 测量。
- **失败**：`失败尝试数 / 窗口尝试总数`，与延迟统计分开。错误 HTTP 响应、超时和 fetch 拒绝均算失败尝试。`no-cors` opaque 响应可计时但读不到状态码，标为“未验证”，不得由这个次数比值推断 HTTP 成功率或丢包率。

P50 与当前值是最易读的主数据；P95、变化幅度、样本数只提供当前路径的尾部与稳定程度。不要跨域名给出“总平均网速”或未经校准的游戏/视频质量分数。

## 固定边界的图形

每个探针在刷新前即分配固定的宽、高与列数。更新样本只更换已有位置里的数字、量化色块或中位标记；容器大小、图表坐标、刻度、卡片、行高和其它文本不随样本值改变。当前数值选用等宽数字；数字位数使用等宽字体，单位和数据槽预留固定宽度；保留轻量 Magic UI 数值插值，遵循 `prefers-reduced-motion`。

主选 **固定六档直方图**：每个探针共用区间 `[0,50)、[50,100)、[100,250)、[250,500)、[500,1000)、[1000,∞) ms`，bin 宽、高在首屏确定；每次返回样本只将已发生的计数分配到现有六格，图轴与容器始终不变。格高统一按固定范围 0–100% 缩放 `count / valid`，初次只有一个有效样本时，对应档位可占 100%，样本计数如实显示，不能误解为成熟分布；超过 1000 ms 的值留在末档并配 `1000+`，避免自适应扩大 y 轴。该图看的是一个目标最近窗口内的延迟分布，不能跨目标合并计数。数字单独显示最新延迟和 P50；P95 在有效数达到 40 时出现。这样密集采样时仍能看到低延迟常态、长尾和失败，而不用让单次最新读数变成一个放大的点。

横轴显示六个固定分段标签（手机可简写），直方图宽度与六个格子的槽位固定。柱高只表示该目标窗口内的样本占比，坐标最高点固定为 100%，不能按当前最大档位动态缩放；延迟高于 1000 ms 时保留在最后一个 `1000+` 档。失败计入单独的数字，不在分布柱中伪造延迟。若更新标签或数字，整块直方图 bounding box 与轴范围保持首屏值。

首页统计若突出一个“当前网络”卡片，仅用同一个基准目标（建议 Cloudflare）展示当前、P50、满足最小样本门槛的 P95 和 HTTP 延迟变化，并明确标出目标。大陆和海外分组只用于筛选/标签，八个目标各自呈现最新延迟与 P50；点选目标后，固定摘要区切换到该目标的六档分布；不得将不同服务目标合并成一个百分位。

## 颜色和异常值

图表只负责延迟分布，探针状态由文本和颜色承载；延迟当前值直接显示数字。建议用深色正文与明亮正文色满足 WCAG AA 普通文本 4.5:1 对比度；背景色、边框和正文不能靠“荧光绿代表一切”承载信息。成功、超时、失败、未验证同时配文字/符号，因此色觉差异和灰度模式仍能读出状态。直方图只编码固定毫秒区间，不要切换全图颜色以宣称某个绝对毫秒值好坏；不同目的地的时延基线不同。

超时没有 RTT 值，显示失败符号而非拿 `4500 ms` 假装测得 4500 ms 延迟。HTTP 500 有一个已读到响应头的耗时，却不是有效响应；原始耗时留在导出样本里，界面当前读数显示破折号，状态标失败，分布和分位数不纳入该样本。对真实成功请求的高值不要统计时剔除：P95 包含可观测的长尾，以帮助发现抖动。显示故障造成的缺样，不插值，不画成零，不用平滑或动画遮住尖峰。

## 屏幕优先级与验收

手机上优先显示单个当前数值和八项探针当前读数；P50/P95 缩为稳定的短标签或在每行末尾，不再垒叠长解释面板。采用固定区域：顶栏和操作约一行、四个关键概览约一行、探针分组与固定区间图填充余下空间。桌面可以加宽栏位，禁止让宽屏空白放大走势图或让小屏把八个目标拆成需要上下滚动的多张高卡片。压缩到真实可读字号以下时，应根据设备高度折叠非关键分布详情，不得用 `overflow:hidden` 隐藏探针、按钮或单位。

可验收条件：

1. 在 320×568、375×667、390×844 手机竖屏、667×375 横屏和 1366×768 桌面浏览器视口中，首页主要状态、四个大陆探针、四个海外探针、固定区间直方图及暂停/间隔/语言控制都在一屏内，不出现页面级竖向滚动或水平滚动；按浏览器缩放/字体放大也不裁切控件与读数。具体检测必须使用实际浏览器可视尺寸，避免用较宽的桌面模拟替代手机验收。
2. 连续观测 20 个周期后，重新取样只更新原有数字和六个区间计数；任一探针卡片 bounding box 宽、高、所在分组以及固定直方图的像素边界与首屏相比保持一致。
3. 向同一目标依次提供 `40, 50, 60, 500 ms, timeout, 70 ms` 等样本，验证超时不进入六档分布、不产生 4500ms RTT；响应色/符号能区分状态；统计不跨越失败计算 jitter，且高延迟值保留在 P95 中。
4. P95 在样本数 39 时未显示统计值，40 时才显示；总样本窗口超过 60 时旧样本按时间移出，固定六个分段与 0–100% 图轴不改变。
5. 固定色彩和普通文字达到 WCAG AA 对比度；颜色编码均有可见文本/形状对应，动效可按系统减少动态设置关闭。
