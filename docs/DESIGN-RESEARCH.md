# Ping visual composition research (v4)

## Direction

Treat Ping as a compact network instrument: the connection identity is the opening anchor, and eight like-for-like probe cards are the working surface. Use editorial hierarchy and a purposeful grid to make the dense data feel composed. Keep the current three local type families and the existing wordmark; keep provider identifiers small and consistent, and avoid unnecessary icons. No slogan, intro paragraph, placeholder tiles, or empty hero area.

The composition can be asymmetric where the data is different: give the richer IPinfo identity card the left 7fr and the Cloudflare route card the right 5fr. Keep the eight probe cards equal in size and use the same linear 0–1,000 ms axis in every card so visual emphasis does not distort comparison. Use the negative space between meaningful groups, rather than unused space inside them.

## Recommended layout

| Viewport | Composition | Fit and density target |
| --- | --- | --- |
| 1440 × 900 | Center a 12-column canvas at about 1,320 px. Header first; then one connection row with IPinfo spanning 7fr and Cloudflare 5fr. Below it, put China and International in equal 6-column region panels. Each region has four equal, vertically stacked probe cards. | Probe cards get the full remaining height and have a comfortably wide box plot. Use a 32 px outer margin and a consistent 16 px gutter; do not stretch one probe card or chart farther than another. |
| 667 × 375 | Use a compact 44 px header and a single compact connection row. Keep the two regions side by side; each region lays out its four probes in a 2 × 2 grid. | Preserve all eight cards, the two connection summaries, plot axes, latest values, P50/P95, and status. The metadata cards can use two concise aligned lines at this height. |
| 320 × 568 | Use a 44 px header; place the two connection summaries in a compact two-column row. Keep China and International in two columns, each with four vertically stacked probes, to preserve regional orientation. | Four probe rows total, two cards per row. Keep the header order: live/sample cadence, theme, More. A concise one-line session footer can hold elapsed time, checks, and failures. No extra help or marketing copy. |

Use content-driven breakpoints rather than stretching a single desktop layout down to phone width. Material's responsive-grid guidance is a useful reference for changing column counts, margins, and gutters at breakpoints; its exact measurements need not be copied into Ping ([Material responsive grid](https://m1.material.io/layout/responsive-ui.html)).

## Composition principles applied to Ping

- **Bento grid:** Make spans express relationships: IP identity is the larger opening card; transport/edge details sit beside it; the eight measurements remain a repeated comparison set. Avoid generic feature cards with icons, descriptions, and calls to action. Magic UI's Bento example is a three-column collection of feature cards, so use its compositional idea while keeping Ping's data card semantics ([Magic UI Bento Grid docs](https://magicui.design/docs/components/bento-grid)).
- **Asymmetry:** Confine unequal spans to connection metadata, where the fields differ in amount. Keep China and International panels equal, and keep all probe cards and chart frames equal. This gives the page a focal point without making one measured target appear more important or more responsive.
- **Breathing room and negative space:** Create space at the boundary between header, connection identity, and measurement groups. Use a small, consistent spacing scale (4/8/12/16 px) inside and between cards. Do not add a large blank banner to manufacture “breathing room.” A spacing scale helps the eye distinguish relationships consistently; GOV.UK documents a responsive spacing scale as one practical model ([GOV.UK spacing](https://design-system.service.gov.uk/styles/spacing/)).
- **Pixel alignment:** Align the brand, region headings, card edges, and chart axes to the same grid lines. Use tabular figures for latency, IP, ASN, and counts; reserve a fixed width for changing values. Every chart uses the same fixed 0–1,000 ms linear coordinate mapping and the same endpoint/tick positions. Keep plot height, label baseline, and card padding fixed while samples arrive.
- **Radius hierarchy:** Use a clear radius hierarchy: 16 px for the lead connection surface, 12 px for probe data cards, and 8 px for controls, with smaller derived radii on compact badges. Pair radius with size, spacing, and surface contrast; do not nest rounded boxes inside every card.
- **Visual anchor:** Let the IP identity (address plus location/network) provide the first large text object. Keep the address masked by default as currently implemented; masking should change the text only, never card geometry. Let the 8 probe readings form the second visual band, with latest values leading each card and the box plot directly below. This keeps the no-slogan product identity clear.

## Magic UI fit

Magic UI describes itself as a copy/paste component collection and offers both structural components and effects. The existing [NumberTicker](https://magicui.design/docs/components/number-ticker) is the strongest fit: it gives the live latency value a restrained update treatment, already uses the installed `motion` dependency, and its implementation calls `useReducedMotion`. Keep it limited to the latest numeric reading; do not animate the card, plot frame, or statistics as a sample arrives. `src/components/magicui/number-ticker.tsx` already includes the upstream attribution and `public/magicui-LICENSE` contains the MIT notice.

| Component | Official API/source notes | Ping recommendation |
| --- | --- | --- |
| [Bento Grid](https://magicui.design/docs/components/bento-grid) | Exposes `BentoGrid` and `BentoCard`; the example uses explicit grid spans. The upstream card also expects an icon, description, destination, CTA, and hover treatment ([registry source](https://raw.githubusercontent.com/magicuidesign/magicui/main/apps/www/registry/magicui/bento-grid.tsx)). | Reuse the *layout principle*, not the marketing `BentoCard` unchanged. Ping's probe cards are measurements, not links or feature promos. The project uses plain CSS and Vite, while the stock component assumes Tailwind utilities and supporting UI helpers. Avoid adding a styling framework just to install a wrapper. |
| [Magic Card](https://magicui.design/docs/components/magic-card) | The official card follows pointer position to reveal a gradient spotlight. Its published implementation also adds Tailwind classes, theme-provider wiring, border effects, and optional orb mode ([official source](https://raw.githubusercontent.com/magicuidesign/magicui/main/apps/www/registry/magicui/magic-card.tsx)). | Use the adapted native-CSS `MagicCard` once, on the larger IPinfo identity card only. It gives the visual anchor a quiet, pointer-local accent; probe cards stay still so the live data remains the only changing signal. No glow on touch or when reduced motion is requested. |
| [Blur Fade](https://magicui.design/docs/components/blur-fade) | Entrance/visibility reveal with `duration`, `delay`, `direction`, `inView`, and `blur` props. | Do not wrap recurring live content in it. If ever used, reveal the whole page once only; it is unnecessary for this compact dashboard. |
| [Border Beam](https://magicui.design/docs/components/border-beam) | An animated beam that continuously travels around a border, controlled by `duration`, `size`, `delay`, and colors. | Skip: perpetual motion would imply activity on individual cards and compete with the live state indicator. |
| [Shine Border](https://magicui.design/docs/components/shine-border) | Animated border sheen with a configurable `shineColor`; installed from Magic UI's shadcn registry. | Skip for the same reason; a persistent border effect has no measurement meaning. |

Magic UI's public repository is MIT-licensed ([repository](https://github.com/magicuidesign/magicui)); retain the license notice for copied code. The project already does this. `src/components/magicui/magic-card.tsx` adapts only the official pointer-following gradient: it accepts native `<article>` props, keeps card content as direct grid children, places an aria-hidden absolute gradient behind them, and updates MotionValues without React state renders. The application stylesheet should set the glow opacity to zero by default, reveal it on hover only for hover-capable pointers, and disable it under `prefers-reduced-motion`. Prefer these two small components over adding a package, a new animation system, or multiple decorative effects. Respect `prefers-reduced-motion`; MDN notes that it requests non-essential motion be reduced or removed ([MDN accessibility media queries](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Media_queries/Using_for_accessibility)).

## Acceptance checks for the next visual pass

1. At 320 × 568, 667 × 375, and 1440 × 900 CSS pixels, all eight probe cards, both connection summaries, and the header controls fit without page scrolling or horizontal overflow at default zoom. No card content is clipped. If enlarged text or a smaller/shorter viewport requires scrolling, content stays reachable instead of being hidden. WCAG's reflow criterion uses 320 CSS px as the narrow viewport target and does not require loss of information or two-dimensional scrolling ([WCAG 2.2 SC 1.4.10](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)).
2. Every update changes readings/marks only: card bounds, plot bounds, labels, and the 0–1,000 ms linear scale remain fixed.
3. The two regions have equal panel weight and all eight plots are directly comparable. Responsive changes alter grouping/column count, not scale or priority.
4. Use text/symbol plus color for live, paused, offline, success, and failure. Verify text contrast at 4.5:1 and meaningful chart/control boundaries at 3:1 against adjacent colors ([WCAG text contrast](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html), [non-text contrast](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)).
5. Check the header's visible order and focus order together: live/cadence → theme selector → More. Keep the first two actions visible; place the manually entered sampling interval (default 3 seconds) in More.
