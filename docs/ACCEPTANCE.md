# Ping acceptance criteria

These checks define observable behavior for the single-page application. Browser dimensions are CSS viewport dimensions. Common desktop, tablet, portrait-phone, and landscape-phone views should fit without page scrolling; very short viewports and enlarged text may scroll vertically to keep content reachable. No layout may clip information or introduce horizontal page scrolling.

## Sampling and statistics

| ID | Acceptance criterion | Check |
| --- | --- | --- |
| NET-1 | Eight public endpoints are probed: Baidu, Bilibili, WeChat, and Taobao in Mainland China; Cloudflare, jsDelivr, GitHub, and Microsoft in International. | Inspect browser requests and probe cards; confirm the 4/4 split. |
| NET-2 | Probes start on page load and run continuously at a 3-second default cadence. The first result per probe is warm-up only, excluded from history, statistics and counters; pause/resume and interval changes do not repeat it. Clearing starts a new warm-up. Options accepts values from 1 to 300 seconds, including decimals, and saves the preference locally. Invalid and out-of-range values do not apply. A target has at most one request in flight; each request times out after 4.5 seconds. | Use controlled requests and clock; check default, decimal and boundary inputs, persistence, in-flight requests, and timeouts. |
| NET-3 | The live control pauses and resumes sampling. Hidden-tab timing is best effort because browsers throttle or suspend background work; returning to the page starts a fresh round immediately with no catch-up burst. Offline state pauses sampling until online. | Advance a controlled clock while paused/offline; background the page and inspect best-effort behavior; confirm a fresh round on return and no catch-up burst. |
| NET-4 | Cloudflare and jsDelivr use CORS and can report HTTP success/error. The other six targets return opaque `no-cors` responses and are labelled HTTP-unverified; their status is not inferred from timing. | Mock CORS success/error, opaque responses, timeout, and rejected-fetch cases; inspect labels and counters. |
| DATA-1 | Each probe shows its latest reading or a clear Timeout, HTTP error, or No reply state; a horizontal box plot with measurement points; P50, P95, jitter, and attempt/failure counts. Failures add no fabricated latency, and a failed latest state dims retained plot history. | Verify cards before and after valid, opaque, failed, and timed-out responses. |
| DATA-2 | Each region shares a linear axis. Its lower bound rounds the lowest valid reading down to 50 ms; the upper bound rounds the highest per-probe P95 up to 50 ms. The minimum span is 50 ms and empty groups default to 0–50 ms. Tick marks have a 50 ms base increment with sparse labels. After five valid readings, Q1, median, and Q3 define the box; Tukey 1.5 × IQR fences define whiskers. Outliers remain visible and do not expand the card. | Test shared regional bounds, fallback/minimum/rounding, known distributions, outliers, five-reading threshold, and fixed plot geometry. |
| DATA-3 | Statistics use the latest 120 completed attempts, with failures occupying positions but excluded from percentiles. P95 is nearest rank and marked ~ below 40 valid readings; failures break jitter adjacency. | Unit tests cover filtering, nearest-rank P95 for early and 40-plus samples, unavailable-at-zero behavior, and adjacent pairs across failures. |
| DATA-4 | Draw every valid reading in the 120-attempt window. Evict the oldest record on append. Retained point nodes/vertical lanes remain stable, with horizontal positions changing only when axis bounds change. Rank-based opacity is 1.0 newest, about .56 at age 30, .34 at 60 and .18 at 119. A valid arrival gets one 900 ms ring; clock ticks and failures do not replay it. | Feed more than 120 samples, compare selected identities before/after an append, inspect DOM identity/coordinates, ring alignment/count and reduced-motion behavior, and verify summary statistics still use the full window. |
| DATA-5 | Probe names use no provider avatars or check glyphs. A small latency-colored dot runs green-to-red from 0 to 500 ms and flashes during measurement; no-reply and timeout states use the danger color. | Inspect the eight probe headers at low, mid, high, pending, and failed states. |

## History and connection information

| ID | Acceptance criterion | Check |
| --- | --- | --- |
| HIST-1 | Each probe retains exactly its latest min(total,120) completed attempts after warm-up, including failures; the eight-probe maximum is 960 records. Lifetime counters continue indefinitely. | Append past the cap and verify counts, newest/oldest timestamps, and continued sampling. |
| HIST-2 | The graph, box plot, P50/P95, jitter, axis bounds and export all use the same 120-attempt window. There is no time cutoff or second display sampler. No window selector is shown. | Check FIFO eviction after 120 attempts, old outlier removal from statistics, rank-based opacity, shared dynamic regional ranges and continued lifetime counters. |
| HIST-3 | Samples exist only in the page session. Clear history resets data/counters and warm-up. | IP-1 | On page load and manual refresh, Tencent DNSPod and Cloudflare (ICanHazIP) each receive separate IPv4 and IPv6 requests. Results stay provider-specific and can be partially available. | Inspect the four requests and mock each provider/family success and failure independently. |
| IP-2 | Both provider cards show IPv4 and IPv6 rows. Addresses start visible; users can hide and copy them. IPinfo location and network metadata refer to the labeled family and fail independently of address lookup. | PRIV-1 | Probe and connection requests go from the visitor's browser to the providers. Ping has no server-side IP lookup, accounts, analytics, or database; addresses are not stored in probe history or exports. | Inspect network destinations, source, sample objects, and exported JSON. Document that contacted providers receive the visitor's normal connection metadata. |

## Verification record

Current local verification: TypeScript check, 30 unit tests, 9 Playwright acceptance tests and rendered-layout checks pass. The tests include initial warm-up exclusion, continuous sampling, dynamic two-sided 50 ms regional bounds, default-visible IPs with masking/copy, observed-address geolocation and rate-limit isolation, the two-icon header and footer Live control, FIFO eviction and stable point identity at the 120-record boundary, one-shot arrival rings and reduced motion. Browser suspension limits remain documented in [BACKGROUND.md](BACKGROUND.md).

Runtime performance checks use a production build with locally intercepted requests, wall-clock measurement windows and separate post-GC retained-memory snapshots. Functional browser tests run separately to avoid contention. See [PERFORMANCE.md](PERFORMANCE.md) for the evidence and metric limits.
