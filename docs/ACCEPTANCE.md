# 验收标准 · Acceptance criteria

以下标准用可复现的行为定义完成状态。实现与验证结果由项目维护者在交付前更新；没有执行的检查保留为“待验证”。

## 功能验收

| ID | 标准 | 验收方式 |
| --- | --- | --- |
| UI-1 | 首页为单页面“网络状态”仪表盘，桌面和 375 px 宽视口都能查看，不出现横向滚动。 | 浏览器检查 1440 px 与 375 px；逐项确认主要面板、控制和状态标签可见。 |
| UI-2 | 所有用户可见文案都提供简体中文和英文；切换语言不刷新页面，并在重新打开后保持所选语言。 | 切换中/英并刷新，检查控制、错误状态、工具提示和 aria 标签。 |
| NET-1 | 首次加载后自动并行测量 5 个公开服务（Cloudflare、Google、GitHub、百度、哔哩哔哩）；每个端点标注名称/区域和测量状态。 | DevTools Network 检查每轮并行请求目标、周期，以及成功/失败状态的显示。 |
| NET-2 | 每个延迟样本使用浏览器单调时钟测量从 `fetch` 开始到响应头可供 JavaScript 使用的时间，单位为 ms；不等待整个响应体。单次请求超时为 4.5 秒。页面清楚说明不是 ICMP ping。 | 对照 Network 面板的响应头时间；模拟端点无响应，确认 4.5 秒内产生超时样本且不会无限挂起。 |
| NET-3 | 测量周期仅可设为 3、5、10 秒；暂停按钮可停止新请求，恢复后继续。任何时刻每个端点最多有一个活跃请求。 | 快速切换周期、暂停/恢复，观察至少 3 个周期；确认无重叠轮询。 |
| NET-4 | 页面进入后台时暂停新的探测；浏览器报告离线时中止正在进行的请求；页面恢复/重新联网后自动恢复。 | 切换浏览器标签；用 DevTools Offline 模拟网络离线并恢复。 |
| DATA-1 | 每个目标最多保留最近 60 个样本；每个目标有独立趋势图，成功与失败都可辨认。顶部当前值、中位数、P95、抖动和失败率仅汇总 Cloudflare 样本。失败会中断抖动相邻样本计算。 | 运行至少 61 个周期；确认首个样本退出窗口；用含失败间隔的样本确认抖动不会跨过失败计算。 |
| DATA-2 | 若显示 IP，默认遮蔽；只有用户主动揭示时显示。导出 JSON 不含 IP、完整 IP 字符串或连接身份字段。 | 初始加载检查遮蔽；主动显示后导出并搜索 JSON 的 `ip`/地址值。 |
| PRIV-1 | 没有 Ping 后端、遥测、账号或数据库。探测只请求列出的 5 个端点；启动时向 Cloudflare trace 发起一次连接概况请求，用户手动刷新时才额外请求。历史只存内存，语言和间隔存本机浏览器；导出不含 IP。 | Network 面板检查请求主机、启动与手动刷新时的 trace 次数；静态检查源码，确认无自有 API/遥测；检查本机存储与导出字段。 |
| DEP-1 | `npm run build` 产出 `dist/`，`npx wrangler deploy` 可把单页应用部署为 Cloudflare Workers 静态资源。 | 干净 checkout 按 README 命令构建；部署后访问首页与深层路径。 |
| CI-1 | GitHub Actions 对 push 与 pull request 执行 install、typecheck、test、build；任一步骤失败使工作流失败。 | 打开 GitHub Actions 的成功运行，确认所有步骤执行完成。 |

## 协作方式

按功能边界并行工作：参考研究确认端点与测量限制，探测模块实现采样和单元测试，前端模块负责交互与中英双语，文档模块维护部署与验收标准。主负责人整合变更，并按上表逐项核验。每个工作结果对应一个或多个验收 ID；未验证项保留为待验证。

## 解释边界

“实时延迟”在本项目中表示按设置周期持续刷新浏览器到公共 HTTP 端点、直到响应头可供 JavaScript 使用的请求耗时。它不测量 ICMP、DNS 单独耗时、带宽或端到端路径，也不保证每个公共服务永远开放。跨域请求若无法读取 HTTP 状态，界面必须标为“未验证响应”，不能当作服务可用。
