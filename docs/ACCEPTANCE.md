# Ping acceptance criteria

These checks define observable behavior for the single-page application. Browser dimensions are CSS viewport dimensions. Common desktop, tablet, portrait-phone, and landscape-phone views should fit without page scrolling; very short viewports and enlarged text may scroll vertically to keep content reachable. No layout may clip information or introduce horizontal page scrolling.

## Product and layout

| ID | Acceptance criterion | Check |
| --- | --- | --- |
| UI-1 | The application has one English-language interface and one “Network status” heading. No locale toggle, Chinese UI copy, slogan, or introductory paragraph appears. | Audit the document language, rendered text, heading, and controls. |
| UI-2 | One page shows Tencent DNSPod and Cloudflare (ICanHazIP) connection cards with IPv4/IPv6 show, copy, and refresh controls; eight probes; two region groups with four probes each; and a session summary. | Verify four address lookups, their controls, eight probe cards, and the 4/4 split. |
| UI-3 | Exactly three local font families are used: Space Grotesk for brand/headings, Inter for interface text, and JetBrains Mono for measurements. The app makes no third-party font requests. | Wait for `document.fonts.ready`; inspect loaded families and resource origins. |

| UI-5 | The header has exactly two matching icon controls: a custom theme listbox and More options. Live/pause with animated activity and cadence sits at the right of the bottom status bar. ## Sampling and statistics

| ID | Acceptance criterion | Check |
| --- | --- | --- |
| NET-1 | Eight public endpoints are probed: Baidu, Bilibili, WeChat, and Taobao in Mainland China; Cloudflare, jsDelivr, GitHub, and Microsoft in International. | Inspect browser requests and probe cards; confirm the 4/4 split. |
| NET-2 | Probes start on page load and run continuously at a 3-second default cadence. The first result per probe is warm-up only, excluded from history, statistics and counters; pause/resume and interval changes do not repeat it. Clearing starts a new warm-up. Options accepts values from 1 to 300 seconds, including decimals, and saves the preference locally. Invalid and out-of-range values do not apply. A target has at most one request in flight; each request times out after 4.5 seconds. | Use controlled requests and clock; check default, decimal and boundary inputs, persistence, in-flight requests, and timeouts. |
| NET-3 | The live control pauses and resumes sampling. Hidden-tab timing is best effort because browsers throttle or suspend background work; returning to the page starts a fresh round immediately with no catch-up burst. Offline state pauses sampling until online. | Advance a controlled clock while paused/offline; background the page and inspect best-effort behavior; confirm a fresh round on return and no catch-up burst. |
| NET-4 | Cloudflare and jsDelivr use CORS and can report HTTP success/error. The other six targets return opaque `no-cors` responses and are labelled HTTP-unverified; their status is not inferred from timing. | Mock CORS success/error, opaque responses, timeout, and rejected-fetch cases; inspect labels and counters. |
| DATA-1 | Each probe shows its latest reading or a clear Timeout, HTTP error, or No reply state; a horizontal box plot with measurement points; P50, P95, jitter, and attempt/failure counts. Failures add no fabricated latency, and a failed latest state dims retained plot history. | Verify cards before and after valid, opaque, failed, and timed-out responses. |
| DATA-2 | Each region shares a linear axis. Its right bound is the largest of its four per-probe P95 values rounded up to a multiple of 100 ms, with a 100 ms minimum and default before valid data. Three ticks show 0, midpoint, and bound. After five valid readings, Q1, median, and Q3 define the box; Tukey 1.5 × IQR fences define whiskers. Outliers remain visible and do not expand the card. | Test shared regional bounds, fallback/minimum/rounding, known distributions, outliers, five-reading threshold, and fixed plot geometry. |
| DATA-3 | Statistics use the fixed trailing 30-minute window. P95 uses nearest rank, appears from the first valid sample, and has a `~` prefix below 40 valid samples. The prefix describes a small-sample estimate; it is not a confidence guarantee. P95 is unavailable (`—`) only at zero valid samples. Jitter is mean absolute change between adjacent valid readings; failures break pairs. | Unit tests cover filtering, nearest-rank P95 for early and 40-plus samples, unavailable-at-zero behavior, and adjacent pairs across failures. |
| DATA-4 | Statistics use every eligible retained sample in the fixed window. Each plot draws no more than 120 valid marks; downsampling changes only the drawing, not summary statistics. Older marks become more transparent with age. Over the 120-mark threshold, stable priority, a recent tail and fixed keys prevent wholesale point replacement. Retained points keep their DOM nodes and vertical positions; their horizontal positions change only when the numeric axis range changes. A valid arrival has one 900 ms clipped expansion ring, disabled for reduced motion; failures and clock ticks do not retrigger it. | Feed more than 120 samples, compare selected identities before/after an append, inspect DOM identity/coordinates, ring alignment/count and reduced-motion behavior, and verify summary statistics still use the full window. |
| DATA-5 | Probe names use no provider avatars or check glyphs. A small latency-colored dot runs green-to-red from 0 to 500 ms and flashes during measurement; no-reply and timeout states use the danger color. | Inspect the eight probe headers at low, mid, high, pending, and failed states. |

## History and connection information

| ID | Acceptance criterion | Check |
| --- | --- | --- |
| HIST-1 | Each probe retains at most 1,200 attempts, including failures; eight probes retain at most 9,600 records. Sampling and lifetime counters continue after the cap, evicting the oldest record per probe. | Append past the cap and verify counts, newest/oldest timestamps, and continued sampling. |
| HIST-2 | Statistics and marks use one fixed trailing 30-minute window; users cannot choose another window. Each plot draws at most 120 valid points and ages opacity by actual sample age. Its linear range adapts to the four per-probe P95 values in that region. At 1 second, the 1,200-attempt cap covers about 20 minutes, so only available retained samples can be shown in the fixed window. | Check the 30-minute cutoff, absence of a window selector, point limit, age opacity, shared dynamic regional ranges, and behavior at the 1-second cap. |
| HIST-3 | Samples exist only in the current page session. Clear history resets retained samples and session counters; refresh or close clears samples. Theme and interval preferences may persist locally. JSON export includes retained samples and counters but no connection IP address. | Clear, refresh, and export; inspect bounds, local preferences, and exported JSON for mocked addresses. |
| IP-1 | On page load and manual refresh, Tencent DNSPod and Cloudflare (ICanHazIP) each receive separate IPv4 and IPv6 requests. Results stay provider-specific and can be partially available. | Inspect the four requests and mock each provider/family success and failure independently. |
| IP-2 | Both provider cards show IPv4 and IPv6 rows. Addresses start visible; users can hide and copy them. IPinfo location, network and time-zone metadata refer to the labeled family and fail independently of address lookup. HTTP 501 is explicitly unsupported; other HTTP and browser fetch failures are unavailable because they do not prove that a family is unsupported. | Verify independent family rows, masking/reveal/copy, partial data, and distinct unsupported/unavailable states. |
| PRIV-1 | Probe and connection requests go from the visitor's browser to the providers. Ping has no server-side IP lookup, accounts, analytics, or database; addresses are not stored in probe history or exports. | Inspect network destinations, source, sample objects, and exported JSON. Document that contacted providers receive the visitor's normal connection metadata. |

## Verification record

Current local verification: TypeScript check, 36 unit tests, 8 Playwright acceptance tests and rendered-layout checks pass. The tests include initial warm-up exclusion, continuous sampling, per-100 ms regional bounds, default-visible IPs with masking/copy, family-specific geolocation and rate-limit isolation, the two-icon header and footer Live control, stable point identity above 120 marks, one-shot arrival rings and reduced motion. Browser suspension limits remain documented in [BACKGROUND.md](BACKGROUND.md).

Runtime performance checks use a production build with locally intercepted requests, wall-clock measurement windows and separate post-GC retained-memory snapshots. Functional browser tests run separately to avoid contention. See [PERFORMANCE.md](PERFORMANCE.md) for the evidence and metric limits.
