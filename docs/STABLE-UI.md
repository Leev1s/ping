# 固定范围数据界面研究

## 结论

把 **中位延迟与 P95 数字**作为主读数，把 **固定槽位的小倍图**作为变化背景。八个探针分成「中国大陆」与「全球」两个固定区域，每个探针各占固定高度的一行。每行显示服务名、当前值、状态和一条固定尺寸的 60 槽延迟带。新样本只填入下一个预留槽；数字用等宽数字原位替换。更新不得增加行数、图形高度、容器宽度，也不绘制一个占满版面的游走点。

Cloudflare Speed Test 页面将下载、上传、延迟、抖动分开展示。它的开源测量模块使用浏览器 `PerformanceResourceTiming` 读取请求耗时；空闲和下载/上传负载下的延迟及抖动是不同指标。项目当前只有轻量的 HTTP 响应头采样，因此可以沿用延迟与抖动统计方法，不能显示下载、上传、负载延迟或网络丢包。Cloudflare 对抖动的定义是相邻延迟样本绝对差值的平均数；失败样本应中断相邻配对。来源：[Speed Test 页面](https://speed.cloudflare.com/)、[Cloudflare speedtest 源码与结果 API](https://github.com/cloudflare/speedtest)。

## 视觉与统计取舍

| 信息 | 建议呈现 | 读法与边界 |
| --- | --- | --- |
| 最新样本 | 每个探针一格等宽数字；固定数字位宽，小数精度固定。 | 一眼看当前延迟。用 `font-variant-numeric: tabular-nums`，单位分列；位数变化也不得推挤邻项。 |
| 一段时间的典型值 | 区域汇总的中位数 P50 与 P95 数字，固定宽度。 | 中位数不被单个尖峰拉动，P95 展示较差尾部。始终附 `n/60` 成功样本数；样本很少时仍展示描述性数值，但把样本量标清。 |
| 近期波动 | 每目标固定 60 槽、相同纵轴的微型时间序列；在一条细带上以短竖线表示样本，并用窄分位区间表示 P25–P75。 | 读整体范围与趋势，不让每次更新重算大小或移动布局。按时间排序，失败槽保留空位并有独立文字状态。八条轨迹用共享刻度便于比较。参考 Tufte 对高密度小倍图和 sparkline 的描述；这里只借用小而直接的趋势上下文，不使用大面积趋势卡片。来源：[Edward Tufte: Sparkline theory and practice](https://www.edwardtufte.com/notebook/sparkline-theory-and-practice-edward-tufte/)。 |
| 失败与异常值 | 失败槽固定红色符号加文字；超过绘图区上限的值固定画在边界并带箭头，旁边仍显示精确 ms 数字。 | 颜色之外还用形状/文字，失败不等于丢包。固定纵轴保留跨服务比较，极端值不会把其他七条线压成直线。 |
| 抖动与请求失败率 | 两个定宽区域数字，单位和样本口径固定。 | 抖动是当前窗口有效相邻对的平均绝对差；状态未知的跨域探针不可伪装成经过 HTTP 状态验证。 |

不把每个探针再加一张常规大折线图：八张同样宽度的固定带更快扫描、横向比较成本更低。若只想快速判断而不比较走势，当前值和 P50/P95 比迷你图更直接。先显示数值与分位带，移除不帮助区分目标或异常的装饰点、网格、刻度和重复标签。

## 固定几何与首屏

- 首次渲染就创建全部 8 行和全部 60 个样本槽。空值、等待、失败和成功都占相同位置；只有槽位内容和已有数字改变。
- 横轴固定 60 个样本，纵轴建议固定 `0–1000 ms`，不是根据最新最大值自动伸缩。超出范围的样本顶格，并显示精确数字；读图者不会因比例每轮重缩放而误判相对变化。
- 数字使用固定容器 `min-width`、`font-variant-numeric: tabular-nums`、禁用行内换行。保持单位为独立列。字体与首批静态内容一并加载，空数据和错误状态不得删除预留格；延迟加载字体可能让周围内容位移，应预留空间或做好字体度量匹配。[web.dev: reserve space and prevent CLS](https://web.dev/articles/optimize-cls?hl=en)。
- 用明确 `grid-template` / 固定行高与图表 `viewBox`；不让样本数驱动 CSS 高度，不为新样本添加 DOM 行，不把自动增长图表放进主页面。
- 使用三个有清楚职责的自托管字体家族：一款简洁的界面无衬线、一款简体中文黑体、一款等宽数字字体；同一家族的 regular/medium/semibold 字重不算新家族。通过静态预加载、控制中文字体切片和固定数字字宽减少加载、换行及布局漂移。
- 页面标题只留「网络状态」及简短实时状态；删除 slogan、介绍段落、卡片解说和页面底部宣传。数值、服务名、区域名、状态文字、操作都应在一个视口内；移动端使用两列区域与触控友好的控件，桌面加宽信息而不加大纵向留白。

## 可访问性边界

高反差主题同样要以可测量对比度选色：WCAG 2.2 AA 的一般文字至少 4.5:1，较大文字至少 3:1；状态不能只靠颜色区分。[WCAG 2.2，SC 1.4.3](https://www.w3.org/TR/WCAG22/#contrast-minimum)。可点击控件至少满足 24×24 CSS px 的 WCAG 2.2 AA 最小目标或满足规定间距例外；优先把常用移动端控件做成 44px 高，符合更易触达的增强尺寸。[WCAG SC 2.5.8](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum)、[SC 2.5.5](https://www.w3.org/WAI/WCAG22/Understanding/target-size-enhanced)。文本放大 200% 时不得裁切或隐藏。[SC 1.4.4](https://www.w3.org/WAI/WCAG22/Understanding/resize-text.html)。

**验收“不下滑”应定义为常见视口的一屏默认阅读体验**，并测试 320×568、375×667、390×844、667×375、768×1024、1366×768、1440×900 CSS px。极矮横屏、系统字体放大或 200% 页面缩放必须允许垂直滚动以保留可读文字、触控空间和完整内容。WCAG 的 reflow 要求在等效 320 CSS px 宽度避免双向滚动，并不要求整页永远不出现纵向滚动；强行让所有设备和缩放都零滚动会导致裁切或过小目标。[WCAG 2.2，SC 1.4.10](https://www.w3.org/TR/WCAG22/#reflow)。

## 验收方法

在空数据、8 项成功、失败/超时、超出 1000ms、最长本地化标签及实时滚动 60 个样本时分别截取同一组视口。断言网格尺寸和各行 bounding box 不变，滚动宽度不超过 viewport；普通竖屏默认滚动高度等于视口高度，缩放和矮横屏仍可读、完整，并允许滚动。测量主要文字前景/背景对比度和触控目标边界。停留至少一个探测周期，观察每个槽只更新内容，容器与其它探针位置固定。

## v2 最终取舍

研究中的 60 格小倍图作为候选方案保留。最终首页采用八个固定卡片显示当前值与 P50，只在一个预留摘要区展示所选目标的固定六档直方图；相比八条微型趋势带，减少图形噪声，并把更多空间留给数字与触控。横轴和 0–100% 纵轴都固定，P95 至少 40 个有效样本才显示。具体实现和已执行验收见 [设计决策](DESIGN.md) 与 [验收记录](ACCEPTANCE.md)。
